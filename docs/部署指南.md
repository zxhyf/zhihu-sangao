# 部署指南：把智护三高放到一台长期运行的服务器上

> 目标：拿到一个**不会变**的网址，评委随时能打开。
> 应用本身零第三方依赖，任何一个能跑 Python 3.9+ 或 Docker 的地方都行。

---

## 先说结论：三种托管怎么选

| 方式 | 适合 | 拿到什么网址 | 费用 | 上手时间 |
|---|---|---|---|---|
| **A. Fly.io**（推荐，最省事） | 不想买服务器、不想管系统 | `https://zhihu-sangao.fly.dev` | 约 ¥15–30/月（按用量） | 10 分钟 |
| **B. 云服务器 + Docker** | 国内评委为主，要快 | `http://你的IP:8080` | ¥40–60/月 | 30 分钟 |
| **C. 云服务器 + systemd**（不用 Docker） | 想少一层依赖 | 同上 | 同上 | 20 分钟 |

三者都已经准备好配置文件，在 `deploy/` 目录下。

---

## A. Fly.io（最快）

前提：注册 fly.io，装好 `flyctl`（Windows 用 PowerShell 安装脚本）。

```powershell
cd C:\Users\22151\Desktop\三高

fly auth login
fly launch --no-deploy --copy-config --name zhihu-sangao
fly volumes create sangao_data --size 1 --region hkg
fly secrets set APP_PASSWORD=你的密码
fly deploy
```

完成后：

```
https://zhihu-sangao.fly.dev/?k=你的密码
```

要点：
- `min_machines_running = 1` 已设，避免评委点开时等冷启动
- 数据在 Fly 的卷上（`/app/data`），重新部署不丢
- 想用自己域名：`fly certs add 你的域名`，按提示加 CNAME

---

## B. 云服务器 + Docker（国内访问最快）

1. 买一台轻量应用服务器（1 核 1G 足够），系统选 Ubuntu 22.04
2. 安全组放行 **8080** 端口
3. 登录服务器后：

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-plugin git
git clone https://github.com/zxhyf/zhihu-sangao.git
cd zhihu-sangao
sudo APP_PASSWORD=你的密码 docker compose -f deploy/docker-compose.yml up -d --build
```

4. 浏览器打开：

```
http://服务器公网IP:8080/?k=你的密码
```

要点：
- **不要用 80 端口**：国内大陆服务器对 80/443 有备案要求，用 8080 就不需要
- 数据库落在 `./data/health.db`，容器重建不丢
- 更新代码：`git pull && sudo docker compose -f deploy/docker-compose.yml up -d --build`

---

## C. 云服务器 + systemd（不用 Docker）

```bash
sudo apt update && sudo apt install -y python3 git
sudo git clone https://github.com/zxhyf/zhihu-sangao.git /opt/sangao
sudo cp /opt/sangao/deploy/zhihu-sangao.service /etc/systemd/system/
sudo nano /etc/systemd/system/zhihu-sangao.service   # 改 WorkingDirectory 与 APP_PASSWORD
sudo systemctl daemon-reload
sudo systemctl enable --now zhihu-sangao
sudo systemctl status zhihu-sangao
```

访问 `http://服务器IP:8080/?k=你的密码`。

## 部署后必做的 5 项验证

```bash
# 1. 服务在跑
curl -s http://127.0.0.1:8080/api/health

# 2. 未登录被拦
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/api/bootstrap   # 期望 401

# 3. 管理接口关闭
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/api/tools       # 期望 403

# 4. 时区正确（应是北京时间）
curl -s http://127.0.0.1:8080/api/health | grep -o '"env":"[^"]*"'

# 5. 统计
docker logs zhihu-sangao --tail 20     # 或 journalctl -u zhihu-sangao -n 20
```

再打开页面点三下：首页三步引导 → 点「记录一次血压」→ 切「用药打卡」，都能用就通过了。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面能开，但一操作就 401 | 没带 `?k=` 且未登录 | 用带 `?k=密码` 的完整链接 |
| 打开很慢（10 秒以上） | 免费/休眠型实例冷启动 | 设最小实例数为 1（Fly 已配） |
| 日期差 8 小时 | 容器时区是 UTC | 已固定 `TZ=Asia/Shanghai`，确认环境变量生效 |
| 数据重启就没了 | 没挂卷 | 确认 `APP_DATA_DIR` 指向挂载点 |
| 链接仍会变 | 用的是临时隧道 | 隧道只适合演示；长期用 A/B/C |
