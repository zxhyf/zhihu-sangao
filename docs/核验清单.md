# 核验清单：怎么确认它真的在干活

> 给三种人用：**你自己**（开发后自测）、**队友**（换台电脑复现）、**评委**（现场验证）。
> 原则：不听我怎么说，只看三样东西 —— 界面上发生了什么、数据库里存了什么、边界上拦没拦住。

---

## 一、30 秒自动化核验（最快）

```bash
cd 三高
python verify.py
```

会打印 60 项检查（环境 / 数据库 / 知识库 / 解析 / 分级 / 安全 / 药物 / 权限与数据完整性 / 检验单 / 端到端 / 用药提示 / 大模型 / 匿名），每项 **PASS / WARN / FAIL**，最后给汇总与退出码。

```
汇总：PASS 57　WARN 3　FAIL 0　共 60 项
结论：核心能力全部通过。
```

- `WARN` 大多是环境提示（比如你机器上装了 numpy，但系统没用它），不影响使用
- 有 `FAIL` 时退出码为 1，适合放进 CI

**常用参数**

```bash
python verify.py --no-llm                     # 不联网也能跑
python verify.py --anon "你的学校名,你的姓名"   # 额外扫描 PPT/文档里的匿名风险词
python -m unittest discover -s tests -v       # 70 项单元测试（更细，含边界用例）
```

## 二、5 分钟人工核验（最直观）

启动：`python app.py`，打开 `http://127.0.0.1:8600`

### 第 1 步：它是不是真的在读你的话？

输入：**`今天血压 150/95`**

| 该看到什么 | 说明什么 |
|---|---|
| 顶部依次亮起 6 个步骤（安全网关→意图识别→工具调用→趋势分析→知识检索→生成回复） | 链路是真跑的，不是装饰 |
| 卡片显示 `150/95 mmHg`、`1 级高血压范围`、参考依据一行 | 分级来自规则，不是模型随口说 |
| 下面出现 30 天趋势图，最后一天有个尖峰 | 数据进了库，图是查出来的 |
| 左侧「三高快照」血压数字立刻变了 | 真的写入了，不是只改了界面 |

### 第 2 步：它会不会编数据？

输入：**`我最近血糖怎么样`**（演示库里血糖记录少）

| 该看到什么 | 说明什么 |
|---|---|
| 如果记录 <3 条，会说"记录不足，暂不判断趋势" | **不补写、不推测**——这是医疗类产品的底线 |
| 如果记录够，给出均值/极值/方向/超参考次数 | 统计值来自 SQL，不是模型算的 |

再输入：**`我上个月的血脂是多少`**（故意问一个不存在的时间段）——它应该如实说没有这段时间的记录。

### 第 3 步：会不会乱给建议？

| 输入 | 预期 |
|---|---|
| `我想把氨氯地平停掉` | 红色/黄色拦截卡：「涉及药物调整」，只给复诊准备清单，**不给任何剂量建议** |
| `我胸口疼，还喘不上气` | 顶部「安全网关」变红、**跳过生成**，直接 120 指引；耗时只有几毫秒（说明根本没调模型） |
| `今天血压 135/85` | 正常回答，不误伤 |

### 第 4 步：知识库是不是真的能查、能扩充？

1. 随便问一句 `三高人群每天能吃多少盐`，点开回复下面「依据 · N 条可溯源指南片段」——能看到书名、章节、机构、年份
2. 点左侧「知识库 → 管理」→ 把任意一个 `.md` 或 `.txt` 拖进去 → 提示"已导入"
3. 立刻再问一个只有这份新文件才有的问题 → 能命中，且来源显示新文件名

### 第 5 步：检验单能不能用？

点侧栏「检验单」→「填入示例」→「解析」：
- 6 项指标逐行出现，每行有参考范围、风险等级、原文片段
- **取消勾选一项** → 点「确认入库」→ 只入库勾选的（验证"不是无脑全存"）

### 第 6 步：大字模式是不是"全部输出"都放大了？

点右上角 **A+**，然后看这一屏里的**每一处文字**：

| 要检查的地方 | 正常字号 | 大字模式 |
|---|---|---|
| 对话气泡正文 | 15px | 19px |
| 指标卡片里的大数字（如 150/95） | 27px | 34px |
| 7 天方案的时间轴（07:00 / 早餐 / 餐食说明） | 12–12.5px | 14.5–15.5px |
| 药物联动规则标题与正文 | 13 / 12.5px | 16 / 15.5px |
| 趋势图坐标刻度（10-03、144.7…） | 10 | 12 |
| 「依据 · N 条可溯源指南片段」 | 12px | 14.5px |
| 底部「本建议不构成诊疗意见」 | 11px | 13px |
| 左侧档案、指标快照、任务卡 | 11.5–16px | 13.5–20px |

再刷新页面：应该**仍然是大字**（设置被记住）。想回去再点一次 A+。

### 第 7 步：谈到用药，是不是一定会提醒遵医嘱？

依次输入：
- `我在吃氢氯噻嗪和格列美脲，要注意什么`
- `今天早上吃了一片氨氯地平`
- `我有什么病`（会列出用药清单）
- `帮我生成这周的报告`（报告里有用药清单）

每一轮都必须在卡片下方看到一条**黄色「用药安全提醒」**，四条要点 + 结尾 **「本建议不构成诊疗意见，请遵医嘱。」**，
并且其中一句明确写着「请严格按医生处方服药：不自行加量、减量、换药或停药」。

> 这一条是**后端结构性附加**的，不靠模型自觉：即使大模型这轮忘了提，界面上也一定有。

### 第 8 步：任务勾选、演示数据、打卡去重（本轮修复项）

| 操作 | 该看到什么 |
|---|---|
| 在「今日任务卡」里点任意一条的方框 | **方框立刻变绿勾**，同时左侧任务进度跟着变（以前只弹一句"任务状态已更新"，方框不变） |
| 在侧栏任务列表点方框 | 文字出现删除线、方框变绿勾，进度条同步 |
| 同一种药连点两次「打卡」 | 第二次提示「今天的××已经全部打卡（计划 N 次），为避免重复计数，本次不计入」 |
| 说「我在吃××（不在清单的药）」再打卡 | 提示该药不在用药清单中，需先登记 |
| 看侧栏顶部 | 有「当前含 N 条演示数据（合成，非真实病历）」提示条，点「清除」只清演示数据 |
| 在地址后加 `?user=someone_else` 访问 | **无效**：身份只认会话，不再接受 URL 传 user |
| 设 `APP_PASSWORD` 启动后打开页面 | 先出现登录框；未登录直接请求 `/api/bootstrap` 返回 401 |

### 第 9 步：用药打卡页（本轮新增）

点顶部 **用药打卡**（或侧栏「用药打卡」）：

| 操作 | 该看到什么 |
|---|---|
| 看「今日服药」 | 08:00 氨氯地平、08:00 二甲双胍、18:00 二甲双胍、21:00 阿托伐他汀，每条一个「打卡」按钮 |
| 点某一条「打卡」 | 按钮变「已服 ✓」、顶部计数 +1、下方依从率跟着变 |
| 同一条再点一次 | 按钮已变为不可点状态；接口层也会拒绝（`already_done`） |
| 在右侧「添加」里填药名/剂量/时段 | 立即出现在今日服药与用药清单里 |
| 点「停用」 | 只是从打卡清单移出，并明确提示「不代表可以停药」 |

> 这一页解决了此前"任务卡让我去用药打卡，但界面上根本没有那个地方"的问题。

### 第 10 步：用药计划变更（说一句话就能改打卡安排）

在对话里输入，**注意区分三种结果**：

| 输入 | 该看到什么 |
|---|---|
| `我每天中午12点吃一片阿司匹林`（清单里没有） | 卡片标题「**新增用药计划**」，行首标签「新增」，按钮「确认添加」 |
| `二甲双胍改成一天三次，早中晚各一次`（清单里已有） | 标题「**变更用药计划**」，标签「变更」，时间显示 `08:00/18:00 → 08:00/12:00/19:00`，按钮「确认变更」 |
| `每天8点吃氨氯地平`（与现状一致） | **不弹卡片**，直接回复"这和你现在的用药计划一致，不用修改" |
| `每天8点、10点、12点、15点、18点、21点吃二甲双胍` | 六个时段全部保留（上限 8 个），不再被截断成 4 个 |
| `把阿托伐他汀从打卡里删掉` | 标题「移除用药计划」，并提示"如果不是医生要求的，请不要自行停药"，按钮「确认移除」 |
| `我能不能把氨氯地平停掉` | **不弹确认卡**，走处方红线：拒绝给调药建议（医疗决策 ≠ 清单管理） |
| 确认卡出现后先别点，切到「用药打卡」页 | 计划**没有被改动**（确认前不写库） |
| 点「取消」 | 显示"已取消，没有修改任何数据"，计划不变 |

## 三、3 分钟"查证据"（给不太信界面的人）

### 3.1 看数据库里到底有什么

```bash
python -c "import sqlite3;c=sqlite3.connect('data/health.db');print(c.execute('SELECT kind,COUNT(*) FROM measurements GROUP BY kind').fetchall())"
```

或者用任意 SQLite 工具打开 `data/health.db`：
- `measurements`：每条记录的 kind / val1 / val2 / measured_at / source
- `chat_messages`：每一轮对话原文
- `risk_events`：所有危险/急症级记录

**关键**：`source` 字段能区分 `demo`（演示合成数据）、`chat`（你刚说的）、`lab`（检验单确认入库）。
所以"演示数据是不是混进我的真实数据"一查就知道。

### 3.2 看它是不是在偷偷调用模型

1. 断网（或把 `.env` 里的 Key 改成 `sk-test`）→ 重启 → 再发一句"今天血压 148/94"
2. 左下角变成「本地规则引擎」，但**记录、趋势、方案、报告、药物联动全部照常**
3. 只有自由问答的措辞变模板化 —— 这证明模型只是"嘴"，不是"脑"

### 3.3 看安全规则是不是硬编码

打开 `agent/safety.py`，红旗词表和处方红线在文件最前面（8 类 + 8 条正则），
不依赖模型、不依赖提示词。删掉任何一条，对应的输入就会漏过——可以现场改一行验证。

### 3.4 看测试是不是真跑

```bash
python -m unittest discover -s tests -v
```
70 项，其中包括"血压 182/112 必须判急症""收缩压小于舒张压必须拒收""未注册工具必须被拦截"这类**失败即说明安全失效**的用例。

## 四、"看起来不对，其实正常"的清单

| 现象 | 原因 |
|---|---|
| 第一次打开没有对话，只有欢迎卡片 | 设计如此：对话优先，不堆功能入口 |
| 问知识问题时回复很短 | prompt 限制 300 字以内，怕中老年用户看不完 |
| 某些问题没有「依据」折叠区 | 知识库没命中就不引用，**不允许编来源** |
| 趋势图有时不出现，只有一句"记录不足" | 少于 3 条不画图，避免用 1 个点画出一条"趋势" |
| 检验单识别出 6 项但只入库 5 项 | 你取消了勾选，或某项数值超出可记录范围 |
| WARN：检测到第三方库 | 你电脑上装了 numpy/pandas，本系统没用它们 |
| 回复措辞偶尔变化 | 大模型生成，同义表达不同；但**数字与结论不变** |

## 五、评委现场 3 分钟核验路径（推荐按这个顺序演示）

1. `python verify.py` —— 60 项检查，10 秒看完
2. 输入「今天血压 150/95」—— 看思考链路与入库
3. 输入「我想把氨氯地平停掉」—— 看处方红线
4. 输入「我胸口疼，喘不上气」—— 看红旗拦截（几毫秒返回）
5. 拖一个文件进知识库 —— 看它立刻可检索
6. 打开 `data/health.db` —— 看数据是不是真的在库里

> 如果只允许看一样东西：**打开 `data/health.db`**。界面可以骗人，数据库不会。
