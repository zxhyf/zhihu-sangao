# 演示脚本（3 分钟录屏 / 现场答辩）

> 目标：在 3 分钟内让评委看到 **agent 的思考过程、数据的真实性、安全的边界、方案的可执行性**。
> 录制前：关闭多余窗口，浏览器缩放 100%，窗口 1440×900 以上；`python app.py` 已启动。

---

## 0. 准备（录制前 2 分钟）

```bash
cd 三高
python app.py
```

- 确认终端打印的地址（默认 `http://127.0.0.1:8600`）
- 确认左下角显示「DeepSeek 在线 · deepseek-chat」（若显示「本地规则引擎」也不影响演示，见第 6 节应急）
- 点侧栏「清空」→ 重新点「演示数据」，保证数据是干净的近 30 天曲线

**口播开场（15 秒）**：
> 这是智护三高，一个面向三高共病人群的健康管理智能体。它不做诊断、不开处方，只做三件事：
> 把零散的数据记下来、看懂趋势、告诉你明天具体做什么。

---

## 1. 记录一次血压（0:15 – 0:45）

**输入**：`今天血压 150/95`

**讲解要点**：
- 顶部依次亮起：安全网关 → 意图识别 → 工具调用 → 趋势分析 → 知识检索 → 生成回复（**这是 agent 的思考链路，不是装饰**）
- 卡片显示：150/95 mmHg、1 级高血压范围、指南原文依据
- 下方是**近 30 天趋势图**，能看出从 158/96 一路降到 121/75，今天这次是反弹
- 底部「依据 · N 条可溯源指南片段」——点开展示：来自《中国高血压防治指南（2024年修订版）》

**一句话**：这次数值、这条曲线、这句结论，都不是模型编的，来自数据库和指南。

---

## 2. 看趋势（0:45 – 1:05）

**输入**：`我最近血压怎么样`

**讲解要点**：
- 均值 137/85、区间、方向（下降）、超参考次数
- 强调：**少于 3 条记录时系统会说"数据不足"**，不画图、不猜（可切到看板展示 LDL 只有 2 条时的提示）

---

## 3. 7 天方案（1:05 – 1:40）

**输入**：`给我一份 7 天方案`

**讲解要点**：
- 点日期标签切换（周一 → 周日）
- 每条都是「几点 + 做什么 + 多少克」：07:00 燕麦片 40 g + 低脂奶 250 mL、19:00 快走 30 分钟（约 3000 步）
- 展开「本周备菜清单 / 执行要点」：限盐 5 g、油 25–30 g、每周 2 次鱼
- 说明方案受约束：**会不会做饭、预算、口味、作息、共病**都会改变结果（可在档案里改"我基本不做饭"再生成一次）

---

## 4. 检验单录入（1:40 – 1:55）★ 数据接入

**操作**：点侧栏「三高快照」右上角的「检验单」→「填入示例」→「解析」

**讲解要点**：
- 一份化验单里 6 个指标一次性识别出来：血糖 6.8、糖化 7.5%、总胆固醇 5.6、甘油三酯 2.31、LDL 3.62、HDL 1.02
- 每行都带**参考范围**和**风险等级**，颜色和指南阈值一致
- 关键：**系统不自动入库**——勾掉某一项就不会写入，确认后才进数据库，来源标记为 lab
- 点「确认入库」后，左侧快照立刻更新，趋势图也把这一天接上

**一句话**：OCR 真正的风险不是识别不出，而是识别错了还静默入库；我们把"人工确认"做成了必经环节。

---

## 5. 用药联动（1:55 – 2:20）★ 创新点

**输入**：`我在吃氢氯噻嗪、格列美脲、美托洛尔，要注意什么`

**讲解要点**：
- 系统识别 6 种药物（含用户档案里的），命中 3 条规则
- 红框第一条：**β 受体阻滞剂会掩盖低血糖**——这是最容易被忽视的一条，患者只会出汗，不会心慌手抖
- 第二条：噻嗪类升糖，削弱格列美脲效果
- 第三条：利尿剂 + β 阻滞剂叠加，新发糖尿病风险增加
- 每条都有"该向医生问什么"和出处

**一句话**：分科管理看不见这些交叉，联合管理才看得见——这是我们的第一个创新点。

**别忘了指一下**：卡片下方那条黄色「用药安全提醒」——四条要点，结尾「请严格遵医嘱服药」。
这一条是后端强制附上的，不是让模型临时发挥。

---

## 6. 两道安全闸（2:20 – 2:50）★ 关键

**6.1 处方红线**

**输入**：`我想把氨氯地平停掉`

- 系统不给任何调药建议，只给"复诊该准备什么"
- 口播：能不能停药必须由医生判断，我们不越这条线

**6.2 红旗拦截**

**输入**：`我胸口疼，还喘不上气`

- 顶部「安全网关」变红，**跳过生成**，直接 120 指引
- 卡片列出：拨打 120、不要自行加药、等待救护车时怎么做
- 口播：这种情况下，任何"先在家观察"的建议都是有害的

## 7. 收尾（2:50 – 3:00）

- 点右上角 **A+**：整屏文字（卡片数值、方案时间轴、曲线刻度、来源片段）一起变大——**适老化覆盖的是输出，不只是输入框**
- 切到「健康看板」：五张趋势图一屏
- 切到知识库抽屉：拖入一个新文件 → 立刻变成可检索片段（**展示"知识库可扩充"**）
- 切到「能力与边界」：20 个受控工具 + 代码级禁用清单

**结束语**：
> 它不是又一个健康问答机器人，而是一个有记忆、有工具、有边界的健康管理助手。
> 而且它是可以现场复现的：零依赖运行，74 项测试全通过，知识库可以现在就加文件。

## 8. 应急预案

| 情况 | 处理 |
|---|---|
| 断网 / API 失败 | 不影响：系统自动降级为本地规则引擎，全部功能照常，只是措辞变模板化。不要停下来解释，继续演示 |
| 端口被占用 | 终端会打印实际端口，按那个地址访问 |
| 页面空白 | 确认终端没关；按 F5；或 `Ctrl+Shift+R` 强制刷新 |
| 演示数据被改乱 | 点「清空」→「演示数据」即可恢复 |
| 想快速跳到某个场景 | 地址后加 `#q=今天血压150/95` 会自动发送这句话（录屏一镜到底很好用） |
| 评委问"是不是 Mock" | 打开终端：能看到真实 HTTP 请求日志与响应耗时；打开 `data/health.db` 能看到数据 |

## 9. 答辩高频问题（准备口径）

**Q：和市面上的慢病 App 有什么区别？**
A：它们按病种切，我们按人切。三高共病的人需要的是"我这把药一起吃安不安全、我这周的三个指标一起看是什么样"，单病种 App 结构上给不出来。

**Q：大模型会不会胡说？**
A：数值全部来自工具调用，模型只负责表达；提示词里明确禁止自算数字；没有检索到来源时明确不引用。安全类判断（红旗、处方）完全不走模型。

**Q：医学内容谁审核的？**
A：目前来自公开国家级指南与药品说明书的整理，已联系医生做盲评，尚未完成——这一点我们主动说明，不夸大。

**Q：怎么盈利？**
A：先做 B 端入口（社区、药店、体检），C 端做子女订阅。不靠卖数据，健康数据默认不出本机。

**Q：为什么不用向量数据库？**
A：11 篇文档用 BM25 + 术语表已经够用，而且完全可解释——出了问题能说清"为什么检索到这一段"。规模上去后会换混合检索。
